# Resume bullets and interview questions

Written only from what was measured or tested in this repository; each line links to its evidence. If a number is not here, it was not measured.

## Bullets

- Built CommerceFlow, an event-driven commerce platform: 7 Spring Boot services and a payment simulator over Kafka and PostgreSQL, behind a gateway, with a React web app. Checkout is an orchestrated saga with compensations and a transactional outbox. ([architecture](architecture/ARCHITECTURE.md))
- Proved checkout correctness under failure. 9 scenarios ran against the live stack: killed services, a stopped broker, a cut database link, every message delivered 3 times. All passed 5 runs in a row with 0 violations of the stock, payment and termination invariants. ([report](reports/failure-recovery.md))
- Met a p95 < 300 ms read-latency target at 500 concurrent users in 5 of 5 runs (p95 188–284 ms), with 0 errors in 1.86 M requests, and reported the stress breaking point and a 30-minute soak with the same rigour. ([report](reports/performance.md))
- Traced the gateway's tail latency to the JVM silently choosing the Serial garbage collector in 768 MB containers, which paused it 21 % of the time. Switching to G1 cut that to 2.8 %, and the longest pause across services from 2.87 s to 0.16 s; the median cost was reported as well. ([report](reports/performance.md#the-bottleneck-garbage-collection-in-the-gateway))
- Ran the system on Kubernetes under the restricted Pod Security level. 90 checkouts survived a hung pod and a deleted pod, once each with no duplicates, and a bad release was rolled back with 0 failed requests in 121. Readiness checks only the pod's own database, proven by stopping Postgres and Kafka. ([ADR-0015](adr/0015-kubernetes-on-kind.md), [checklist](CHECKLIST.md#milestone-10--kubernetes-on-kind))
- Wrote Terraform for an AWS deployment and an EKS reference stack, verified without an account. The checks are 16 tests against mocked providers, tflint, and checkov (217 passed, 0 failed); 12 planted security defects were each caught. GitHub OIDC roles name every action, and the instance terminates itself after a few hours. ([ADR-0016](adr/0016-terraform-and-aws-demo.md))
- Made security testable: a black-box suite of 12 tests against the running stack (forged tokens, cross-account access, replays, injection, log and metric scanning), with gitleaks, Trivy and CodeQL in CI, and no untriaged HIGH or CRITICAL findings. ([threat model](security/SECURITY.md))

## Interview questions this project answers

1. **How do you keep a checkout consistent across three services without distributed transactions?** An orchestrated saga with compensations. A transactional outbox, so a state change and its event commit together. Idempotent consumers and idempotency keys at every hop. Invariants checked in the databases after every failure scenario. ([ADR-0003](adr/0003-orchestrated-saga.md), [ADR-0004](adr/0004-polling-transactional-outbox.md))
2. **What happens if the payment provider charges the card but the answer never arrives?** The attempt becomes UNKNOWN, and a reconciler asks the provider what happened, from its records, rather than charging again. The "lost acknowledgement" scenario tests exactly that. ([report](reports/failure-recovery.md))
3. **Your p95 was 20 times your median. How did you find out why?** By comparing server-side latency per service in Prometheus. Catalog and order were at about 24 ms, the gateway at 216 ms. Then the gateway's GC metrics, whose collector names gave away Serial GC. ([report](reports/performance.md))
4. **Why did your median get worse after the fix, and was it still worth it?** G1 trades a little on every request for far fewer long stops. The target was the tail, and p99 fell in every run. Also why one before-and-after pair was not enough: two identical runs differed by 20–30 % at p95. ([report](reports/performance.md#what-the-load-runs-do-and-do-not-show))
5. **What should a readiness probe check?** Only what the pod needs to serve: here, its own database. Never Kafka, or a broker blip takes every pod out at once. Liveness checks the process only. Both were shown by stopping each dependency. ([ADR-0015](adr/0015-kubernetes-on-kind.md))
6. **Your pod-kill test passed but never retried anything. What did that tell you?** That deleting a pod, even a crash, takes it out of the Service before requests reach it. The test now hangs a pod instead, which is the case client retries exist for. ([checklist](CHECKLIST.md#milestone-10--kubernetes-on-kind))
7. **How do you give CI access to AWS without keys, and limit what it can do?** GitHub OIDC with a trust scoped to one Environment that needs approval. Every action named. Rights scoped by tag, name and region. The only attachable policy is Session Manager's, so the role cannot escalate itself. ([ADR-0016](adr/0016-terraform-and-aws-demo.md))
8. **What would you change first for real traffic?** Sample far fewer traces, and size Tempo for it: it was the component that did not hold up under load. Run the load generator on another machine, and the observability stack too. Raise the gateway's capacity for sign-in surges, which broke the fast ramp-up. ([report](reports/performance.md#the-observability-stack-under-load))
